## 填写要点

| 部分 | 要求 | 时长 |
|---|---|---|
| **一句话** | 20 字内 | 1 分钟 |
| **上下文图** | 手画即可，说明"接谁" | 5 分钟 |
| **核心 API** | **只列你实际会用的**，不要抄全表 | 10 分钟 |
| **关键配置** | 同上，只列影响行为的 | 10 分钟 |
| **三个易错点** | 这是最有价值的部分 | 10 分钟 |
| **是否需要** | 直接关联裁剪决策 | 2 分钟 |

> [!important] 不要做的事
> - ❌ 抄完整 API 表（那是文档干的事）
> - ❌ 抄所有配置参数（几百个，抄不完）
> - ❌ 复制状态机图（描述"怎么用"比"长什么样"重要）
>
> ✅ **只记录：你会用的 + 容易错的 + 需要决策的。**

## 示例：COM 速查卡（节选）

```markdown
# SWS_COM 速查卡

> [!tip] 一句话
> 信号↔I-PDU 打包/解包、超时监控、发送模式决策。

## 核心 API
| API | 用途 |
|---|---|
| `Com_SendSignal()` | 发送信号 |
| `Com_ReceiveSignal()` | 接收信号 |
| `Com_TriggerIPDUSend()` | 立即触发发送 |
| `Com_IpduGroupStart/Stop()` | 启停 PDU 组 |

## 三个易错点
| # | 易错 | 正确做法 |
|---|---|---|
| 1 | 字节序与 DBC 不一致 | 对照 DBC 的 @0/@1 配置 |
| 2 | 把自造 Alive/Disabled 当标准过滤枚举 | 按 ComFilterAlgorithm 与 TransferProperty 的真实枚举检查 |
| 3 | 失效值与有效值重叠 | 留出专用失效码 |
```
