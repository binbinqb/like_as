# 分区与多核

> [!tip] 结论
> 分区是软件归属与保护／恢复边界，多核是执行资源。硬件保护、OS 配置、RTE 通信和恢复策略共同决定隔离效果；WdgM 检查点不能替代 MPU 隔离。

## 一、OS-Application 与 EcucPartition

OS-Application 组织 Task、ISR 等 OS 对象，关联配置分区并绑定核。一个 OS-Application 不能任意横跨多个核，但一个原子 SWC 的特殊映射、可重入和实例场景需要结合 RTE／System Template 规则，不能用“一 Runnable 只能一个 Task”推出所有情况。

可信／非可信及特权、保护选项要按实际 OS 类和配置解释；不能一概说所有可信应用都无条件访问全部内存，或任意 BSW 故障都无法遏制。

## 二、保护能力

| 能力 | 依赖 | 局限 |
|---|---|---|
| 内存访问保护 | 硬件保护单元、OS、链接布局 | 需覆盖共享区、外设与 DMA 等路径 |
| 时间保护 | 配置预算、时基和 OS 支持 | 不自动证明所有截止期满足 |
| 分区终止／恢复 | OS 服务、依赖与状态恢复策略 | 关键可信服务不能任意终止 |
| WdgM 监督 | 合适检查点、独立监督路径 | 检测执行异常，不阻止内存破坏 |

SC1/SC2 多核也可有 OS-Application；SC3 主要增加内存保护，SC4 同时包含时间和内存保护。详见 [[04-OS与调度]]。

## 三、多核下 BSW 分布

EcuM 的主／从核流程、各有 BSW 分区中的 BswM 实例、共享外设归属均按模块规范和配置设计。Com 等模块分布不能仅凭“通常一个 Master”就固定。

共享外设应有明确控制者，代理／分发机制不能造成两个核并行改同一套寄存器。缓存一致性、原子访问和内存顺序也需考虑，不能只加 `volatile`。

## 四、IOC 的边界

IOC 提供跨 OS-Application 的数据通信机制。RTE 可以借助 IOC 和通知，将客户端／服务器交互映射为请求与结果数据通道；不能因此声称 IOC 本身提供任意通用 RPC。

共享内存、spinlock、核间中断是实现与协调机制，不是所有业务模块可任意绕开合同访问的理由。是否每次都需要锁、是否有数量级开销，须由实现和测量确定。

## 五、单核 BCM 怎么选

是否需要保护或多核由算力、故障分析、混合关键性和产品约束决定，不是“域控制器一律两者都必须”或“单核 QM 永远不需要”。当前没有确认 MCU 型号和资源，不能将 CVM0146／Cortex-M4F 当成既定平台事实。

文件级封装、单写者、范围检查、快照、CRC 和栈监控可以改善组织与故障检测，但不应称作“软分区等效硬隔离”或据此作功能安全结论。
