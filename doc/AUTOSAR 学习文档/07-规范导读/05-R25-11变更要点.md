# R25-11 变更要点

> [!tip] 结论
> R25-11 的发布日期为 2025-11-27。版本影响要以 ReleaseOverview 的变更、移除、重做清单及模块历史共同判断；不能断言“传统 BCM 几乎无感，唯一破坏兼容性的是 LdCom”。

## 一、发布概览列出的五个引入概念

| 概念 | 准确理解 |
|---|---|
| Vehicle Data Protocol | 面向量产车辆分布式数据采集，解耦采样与传输策略 |
| Revise MACsec Support | 补充／澄清 MACsec 支持、拓扑和处理机制，不是第一次有 MACsec |
| COMHandler | 增强通信错误抽象、监控与报告，将 LdCom 功能合入 Com |
| PRS Time Synchronization Over CAN Protocol | 将协议规范与 CP 实现规范分开，协议部分位于 Foundation |
| DDS Support on Classic Platform | 扩展 DDS 的 SOA 能力、接口和发现等支持 |

这五个是 §2.1.1 的概念清单，不等于本次发布只有五项变化。

## 二、需要纠正的历史理解

- 跨 ECU／ECU 内通信的抽象在 VFB/RTE 中早已存在；COMHandler 不是第一次使组件通过端口通信。
- Com 本来就有发送缓冲与发送模式，不能说传统 Com 强制将采样与发送绑在同一周期。
- CP 在 R25-11 之前已有 SOME/IP 等服务导向通信；DDS 扩展不意味着“CP 从这一版才开始 SOA”。
- LdCom 合并之外，还有存储驱动、API、配置项和旧特性的删除／调整，需要逐项检查。

## 三、存储驱动是规范移除，不是图形调整

ReleaseOverview §2.2.4 明确列出移除 FlashDriver 和 EEPROMDriver 的 SWS／RS。R25-11 存储学习主线应包括 MemAcc 与 Mem，历史 Fls/Eep 可以保留为旧接口背景。

见 [[09-存储栈MemIf-Fee-Fls]]。项目如果继续采用旧供应商栈，要明确其实际标准版本，不必为了最新文档立即改写已验证产品。

## 四、通信链路

```text
旧常见诊断发送：Dcm → PduR → CanTp → CanIf → Can
R25-11 诊断发送：Dcm → PduR → CanTp → LSduR → CanIf → Can
```

R24-11 CanTp 下层由 CanIf 改为 LSduR；R25-11 增加 TP 通道发送请求队列。LSduR 并非只为 CanTp 存在，也连接其他通信服务和硬件接口。

## 五、BCM 升级评估

| 项目 | 检查动作 |
|---|---|
| Com/LdCom | 检查接口、配置、错误抽象和生成器迁移 |
| 存储栈 | 确认旧驱动替代、新 API、地址区域及后端支持 |
| CanTp/LSduR | 检查路由、请求队列、资源与超时 |
| NvM | 读取／写入验证及块配置变更 |
| OS/RTE | 删除的旧能力、接口、任务与生成配置影响 |
| 工具与模型 | 检查实际 schema、生成器、BSW 和 FO 依赖版本 |
| 已知缺陷 | 阅读 ReleaseOverview 第 4 章，并对应所用模块评估 |

上述是学习与评估清单，不是对当前项目已经完成的兼容性证明；不预设供应商支持滞后多少年。

## 六、自检
