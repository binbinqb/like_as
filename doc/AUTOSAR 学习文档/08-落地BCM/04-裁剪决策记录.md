# 裁剪决策记录

> [!tip] 结论
> 以下是待结合产品输入确认的裁剪候选，不是已经批准的产品基线。自建框架按需求选择能力；若声明标准兼容，另行核对该版本的支持范围与可配置项。

## 一、每项决策都要回答

```text
需求与来源 → 需要的行为 → 支持／不支持的范围
          → 依赖、时序与资源 → 验证方式 → 负责人／决策状态
```

模块删除、功能裁剪、行为改变的影响不同。即使整个模块“不用”，仍需证明其他模块没有依赖；不能说模块级裁剪总是低风险。

## 二、BCM 候选清单

| 能力 | 初步方向 | 定案依据 |
|---|---|---|
| MCU／OS 适配 | SDK＋FreeRTOS，定义边界 | 芯片、工具链与调度需求 |
| IO 采集 | 优先建设端点、MUX 扫描与缓存 | 原理图、采样时限与保护响应 |
| 设备驱动 | 按实际器件接入 | RS2260、PCA9555/TCA9539、HSD 等手册 |
| 通信 | 复用 dbcom 已有能力，补语义映射 | 实际中间件 API、DBC 与网络规范 |
| ISO-TP | 若采用 UDS over CAN，支持所需地址／帧／时序组合 | OEM 诊断合同及互通测试 |
| Dcm 风格诊断 | 按服务支持矩阵实现 | DID、RID、会话、权限和时序 |
| Dem 风格故障 | 状态位、记录、清码、持久化按需实现 | DTC 清单与测试规范 |
| 存储 | 选择经过掉电验证的后端 | 存储器、寿命、布局、恢复要求 |
| 网络与电源 | 按节点睡眠／唤醒协议实现 | 不能仅因“没 CanNm”就省全部通信管理 |
| 看门狗 | 至少明确执行健康与触发策略 | QM 也有可用性需求，不能等 ASIL 才考虑 |
| 安全／E2E／SecOC | 是否需要待产品分析 | 不能预先断言没有安全需求 |
| 以太网／DDS／V2X | 没有需求时不纳入首版 | 功能范围与扩展计划 |

## 三、协议范围可以选择，选中的行为不能随意改

“完整 CanTp”不是实现所有可选组合的口号。可以选择支持的总线、地址格式、长度、连接数量，但对于声明支持的组合，SF/FF/CF/FC、序号、流控、超时和错误恢复都要满足对应合同。

UDS 不存在所有 BCM 通用的必选服务清单；DTC 老化、冻结帧等不能在未核对客户需求时直接决定不做。NRC 也不能随意省略而声称外部行为不受影响。

## 四、存储和库的裁剪

保留旧 Fls 接口可以是兼容选择，但要注明不是 R25-11 现行规范。MemIf 单实例可用规范允许的宏映射；有需要时可简化实现成本而保留合同。

CRC、冗余、默认值、写验证、提交恢复各解决不同问题，是否采用逐项决定。MSF 确实标准化 copy/move/fill 等功能，但本版 API 标为 DRAFT，不能据此要求“全部替换 libc”；库的角色见 [[12-库函数与ICC一致性类]]。

## 五、记录模板

| 字段 | 说明 |
|---|---|
| 决策 ID / 状态 | Proposed / Accepted / Superseded 等项目状态 |
| 能力与版本 | 模块／协议／API 和版本 |
| 需求来源 | 官方条目、OEM 文档或项目决定，分开写 |
| 支持范围 | 总线、地址、长度、连接、数据类型等 |
| 不支持范围 | 明确排除项及是否会被配置／调用 |
| 影响与替代 | 应用、诊断、总线、启动与升级影响 |
| 验证 | 正常、边界、超时、复位、掉电等 |
| 负责人／日期 | 实际决策后填写，示例不冒充批准 |

## 六、一个具体候选

不支持 Dataset 块，仅支持 Native＋Redundant，可以作为初期范围候选；需要证明配置与调用均不使用 Dataset，并提供数据多副本需求的替代设计。它不自动证明符合完整 NvM SWS。

不解析对端 STmin、固定按 0 连发，则改变已支持 TP 组合的外部行为，应修正实现，而非记录成“低风险优化”。
