# 2026-11-16

## D1 第二步收官：boot UDS 刷写端到端打通（commit 1625a41）

### 根因（主因）
`Platform_InitTick()` 在 boot 里**从来没被调用**（app 是 EcuM 调的）。
`s_ms` 恒为 0 → `Boot_UdsLoop` 的 `(Platform_NowMs()-next) >= DCM_MAIN_FUNCTION_PERIOD`
永不成立 → `CanTp_MainFunction` / `Dcm_MainFunction` 一次都没跑过。
现象：CAN 收发硬件全好（探针发 8 帧 0x7E8 上位机全收、RX 邮箱 CS.CODE 能看到 FULL），
诊断仪发什么都是彻底沉默（连 NRC 都没有）。

**教训**：这类"所有寄存器证据都绿但就是没反应"的问题，要优先怀疑"主循环/调度跑没跑"，
而不是继续查硬件。没有寄存器能反映"状态机推进了几步"，只能靠计数打点。

### 附带发现
1. **本片 FlexCAN 没有 RXIMR 区**：只解码到 `base+0x87F`（CAN0 base = 0x40038800）。
   读 `RXIMR[5]`（base+0x894）立刻精确总线错 `cfsr=0x8200 BFAR=0x40038894`；
   写会被吞掉（所以 `FlexCanDrv_InitCanRAM` 那段清 RXIMR 的循环一直"正常"）。
   `flexcan_reg.h` 里 `RXIMR/HR_TIME_STAMP/ENHRXFIFO/ERFFEL` 只能当偏移占位，**不能读**。
2. **厂商 startup 把所有异常入口弱别名到同一个 `Default_Handler` 死循环**，
   故障现场不留任何信息，表现是"串口突然没声 + 几秒后复位"。
   新增 `app/boot/src/boot_fault.c` 覆盖 HardFault/MemManage/BusFault/UsageFault，
   打印 `CFSR/HFSR/BFAR/MMFAR` + 入栈帧 `PC/LR/xPSR/SP`。
   要点：`naked` + 内联汇编取 MSP/PSP（序言会改 MSP）；`Boot_FaultReport` 必须
   `__attribute__((used))`，否则 `-Os` 下被当成未使用 static 删掉。
3. boot `-Os` 后 51,276 / 130,048 B，余量充足。

### 实测链路
- 10 02 → `06 50 02 00 32 01 F4`；3E 00 → `02 7E 00`
- `uds_flash.py --elf AppB.exe --slot B --verify`：transfer 100%（203,124 B）→
  `31 01 FF01` CRC OK → `11 01`
- 复位后 boot 选 B（rolling counter）、CRC 一致、`jump to slot B entry=0x090400`，
  app 起来 `boot confirmed for slot B`

### bring-up 工具约定
`CanAc_DbgDump`（寄存器快照）/ `CanAc_DbgProbe`（主动发 8 帧 0x7E8 二分 TX/RX）/
`CanAc_DbgStatus`（每秒 `isr/rx/mb/cs/iflag`），统一由 `BOOT_CAN_PROBE` 控制，
**默认 0** —— 探针会往总线插 8 帧假 0x7E8，刷写时必须关。
