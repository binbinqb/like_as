## Shell 标准化方向（用户拍板，2026-11-12）
- 用户意图：① Bcm_Frame 的 shell 作为模块引入 H:\as（标准 shell + xxx_cmd.c 模式，不用的 cmd 不参与编译）② pyserial 上位机底层标准化 ③ 参考 classic-platform-master 优秀设计 ④ 一切设计必须保证 JSON 编辑器可用并拓展它
- **H:/as shell 现状痛点（实扫）**：main.c 2215 行含 ~30 个 case 的巨型单字符命令 switch（!k/!j/!l/!M 全在这）；letter-shell 引擎根本没参与编译（只有 Can.c/Com.c 3 个遗留注册）；上位机 15 个 m*_check.py 各自实现 serial.Serial 交互
- **Bcm_Frame shell 资产（实扫）**：src/middleware/shell 共 4054 行（sh_core 997 + sh_io 591 + sh_parse 413 + sh_cmd 416 + sh_bg 251 + sh_history 142 + 3 头文件），段注册 SH_EXPORT_CMD（IAR 语法 hal_sh_cmd$$Base/Limit，Bcm_Frame 是 IAR），零动态内存、SCPI 应答协议 `<±n, msg`、循环执行 &period、历史/行编辑、前缀过滤；上位机 scripts/bench/shell.py 251 行（提示符切帧、USB 描述自动找口 CH343、ANSI 清洗、cmd() 原语）
- **classic-platform 可借鉴三点**：SchM 每模块调度头（SchM_Com.h 等 20+ 个，as-master 缺 SchM）；per-module .mod.mk + build_config 编译开关；静态 Cfg.h + 生成 PBcfg.c 分离
- **技术要点**：H:/as 是 GCC(scons)，Bcm_Frame 是 IAR——段注册需把 IAR `$$Base/Limit` 换成 GCC `__attribute__((used,section()))` + `__start_/__stop_` 自动符号（orphan section 不用改链接脚本，需 spike 验证）
- 新里程碑：Shell 标准化插到 M20 后（M21 前提位）——M21~M25 验收全靠串口命令，先标准化基础设施，后续每个里程碑验收成本下降
